# 구현 결정 / 2026-09-21

- 기준 저장소 `Youda0403/Sea`는 작업 시작 시 빈 저장소(default main, size 0). 기존 코드나 사용자 저장 데이터는 없었음.
- 범위: 캐릭터 생성 → 거점 → 침수 창고 → 결과 6종 → 귀환 → 일기 → 에필로그의 하루. 계획서의 전체 MVP보다 작음.
- 실행 의존성을 없애기 위해 첫 프로토타입은 Vite/TypeScript 빌드 대신 **브라우저 네이티브 ES modules + TypeScript 계약 파일**을 사용. `.d.ts`는 참고 계약이며 실제 JS를 정적 타입 검사한 것으로 주장하지 않음. 후속 타입 이행은 별도 작업.
- `content`, `engine`, `storage`, `UI` 분리. 단일 사건 구조를 데이터 기반 범용 엔진으로 과장하지 않음. 확장 경계는 CONTENT_GUIDE에 명시.
- 희귀 거부 확률은 계획서 점수 구간을 따름. 드론 대안은 이 에피소드의 고정 지급 장비로 진행 막힘을 방지. 거부 재추첨 없음.
- 기억·감정은 첫 사건에 필요한 침수 경계/공포·죄책감으로 축소. 전체 믿음 시스템은 미구현.
- 손상 저장의 원본 보호를 우선해 읽기 실패 시 새 게임으로 자동 초기화하지 않음. 원본 JSON 다운로드 제공.
- 현재 저장 + 교체 직전 저장 1개. 일반 플레이는 revision으로 중복 적용을 막고, 새 게임/복원은 이전 저장을 별도 키로 보관.
- 로컬 저장과 JSON 백업만 제공. 유료 서버/API 및 분석·추적 요청 없음.
