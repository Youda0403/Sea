# 콘텐츠 작성 가이드 v2

## 회차 계약

`schedule[1..14]`은 각 날짜에 정확히 두 사건을 둡니다. 첫 사건은 그날의 기본 후보인 `ambient`, 두 번째는 스토리를 진행하는 `main`입니다. `ambient`는 반드시 그날의 기본 후보만 진행하는 것이 아니라, `availableExplorations()`에서 이전에 지나친 장소나 조건부 후속 사건을 포함해 최대 네 후보를 보여 주고 플레이어가 한 곳을 고릅니다. 14일차 main 사건 뒤 일기를 만들면 엔딩으로 이동합니다. 필수 사건을 난수 출현으로 바꾸지 마세요.

흐름은 `베이스 → 자유 탐사 선택 → 사건 1 → 결과 → 사건 2 → 결과 → 귀환 → 일기`입니다. 선택 의도, 캐릭터가 실제로 한 행동, 결과를 분리해 기록합니다. 결과 화면은 서술만 보여 주고 진단 정보는 기록 탭의 접힌 상세에 둡니다.

## 사건 추가

`src/content.js`의 `E()`는 사건 데이터, `C()`는 선택, `O()`는 결과를 만듭니다.

사건에는 고유 `id`, 날짜(첫 등장 가능 시점), `ambient|main`, 제목, 장소, 도입 문장, 선택이 필요합니다. 추가 `ambient` 사건은 `schedule`에 넣지 않고 `add(E(...))`로 등록할 수 있습니다. `requiresFlags`, `requiresAnyFlags`, `excludesFlags`를 사건 수준에 붙여 실제로 기록된 월드 상태로 출현을 제어합니다. 결과에는 실제 행동, 플레이어에게 보여 줄 `text`, 일기·기억의 객관적 사실인 `fact`, 수치 효과를 작성합니다. `fact`에는 성공하지 않은 일을 성공했다고 쓰지 마세요.

일부 선택에 `requiresFlags:['flag_name']`을 붙이면 해당 기록을 확보한 캐릭터만 선택할 수 있습니다. 추가할 때에는 준비가 없더라도 진행 가능한 일반 선택지를 함께 남겨야 합니다. 자율성 판정을 켠 선택에는 같은 사건 안의 유효한 `alternative`가 반드시 있어야 합니다. 대체 행동은 원래 선택과 다른 `actualActionId`를 남깁니다. 강제 명령은 거부 뒤에만 가능하며 행동 시도만 강제합니다.

인물과 직접 조우하는 결과에는 `discoveries:['personId']`를 넣습니다. 새 인물은 `people` 데이터에도 소개를 작성합니다. 이름만 들은 상태는 조우로 처리하지 않습니다.

아이템 보상은 `rewards`, 세계 상태는 `flags`, 엔딩 성향 누적은 `meters`, 기억 태그는 `tags`를 사용합니다. 단순히 플래그를 저장하는 데서 그치지 말고 후속 탐사의 해금, 메인 사건의 새로운 행동, 인물의 재등장, 일기 또는 후일담 중 **최소 한 곳 이상**에서 실제로 다시 읽히도록 설계해 주세요. 공통 엔진 밖에서 상태를 직접 수정하지 마세요.

## 저장 변경

새로운 필수가 되는 필드를 바꾸면 `saveVersion`을 올리고 이전 버전 마이그레이션을 추가합니다. 이번 탐사 선택 ID(`selectedExploration`)는 없을 때 이전의 기본 사건으로 처리하는 선택적 필드라 v2를 유지합니다. v1 저장은 현재 v2로 자동 변환하며, 완료된 1일차 기억과 일기를 보존합니다. 기존 기록을 초기화로 조용히 지우지 마세요.
