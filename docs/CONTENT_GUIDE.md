# 콘텐츠 작성 가이드

## v0.1 계약

선택 의도 → 수용/거부 → 실제 행동 → 결과 → 효과/기억 → 저장 → UI 순서입니다. `transition()`은 입력 상태를 변경하지 않고 새 상태를 반환합니다. UI는 `commit()`이 완료된 뒤에만 결과를 표시합니다. 모든 랜덤 판정은 상태에 저장되는 xorshift32를 사용합니다.

`content.js`에는 함수나 상태 변경 코드를 넣지 마세요. 자유 입력은 HTML로 해석하지 않습니다. `eval`과 외부 AI 호출은 없습니다.

## 기존 사건의 결과 추가

1. `episode.outcomes`에 고유 ID, `action`, `result`, `title`, 장면 `text`, 일기용 객관 `fact`, 수치 `effects`, `tags`, 세계 상태 `flag`를 작성합니다.
2. 해당 행동의 `episode.tables`에 결과를 연결합니다. 누적 `max`는 오름차순, 마지막은 1입니다.
3. 구조 시도와 성공을 구분하세요. 안전을 확인하지 못한 인물을 구조 완료라고 쓰면 안 됩니다.
4. 선택에 자율성을 켜면 유효한 `alternative`를 지정합니다. 강제 명령은 거부 단계에서만 사용되며 물리적 게이트를 우회하지 않습니다.
5. `npm test` 및 브라우저 E2E를 실행합니다. 모든 결과에 도달 가능한 시드가 있어야 합니다.

## 새 사건을 추가할 때

현재는 의도적으로 사건 하나를 수직으로 완성한 구조입니다. 새 사건을 파일에 추가하는 것만으로 자동 연결되지는 않습니다. 다음 단계에서 `episode`를 `episodes[eventId]` 레지스트리로 바꾸고 SaveData에 현재 eventId와 사건별 로그 배열을 도입하세요. UI의 고정 장면과 엔진의 단일 resolution도 함께 일반화해야 합니다. 저장 포맷 버전을 올리고 v1→v2 migration 테스트를 추가하세요. 기존 플레이어 기록을 지우는 초기화는 금지합니다.

새 아이템도 설명만 추가하면 효과가 생기지 않습니다. `items` 정의, inventory 계약, 조건/효과 처리, 저장 검증, UI 사용 확인, 중복 차감 방지 테스트가 모두 필요합니다.

## 일기

완료된 outcome의 `fact`가 첫 문단입니다. 표현은 사교성, 침수 과거, 강제 사용, 죄책감에 따라 달라집니다. 하루 종료 시 텍스트를 저장하고 열람 시 재생성하지 않습니다. 프로필의 과거와 이번 플레이에서 발생한 사건을 혼동하지 마세요.
